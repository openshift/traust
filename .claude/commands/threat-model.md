Build or maintain a threat model for $ARGUMENTS using the threat-model skill. Load the skill at .claude/skills/threat-model/SKILL.md and follow its full procedure — safety preamble (static analysis only, no code execution), then route to the requested mode: `bootstrap` (derive from code + past vulns via a parallel research swarm, five checkpointed stages, optional `--context` doc ingestion), `interview` (four-question framework with the application owner), `bootstrap-then-interview` (code-grounded draft refined with the owner), `review` (measure an existing threat model's drift against the current code, interactively offer to apply; `--auto` report-only / `--apply` accept-all for automation), `update` (targeted changes under ID-stability rules), or `pr` (diff-scoped assessment ending in approve/request-changes; writes no model). `$ARGUMENTS` is `[bootstrap-then-interview|bootstrap|interview|review|update|pr] <target-dir>` — the model file is always named after the target (`<repo>-threat-model.md`, per the skill's naming rule; legacy THREAT_MODEL.md files are still read and are migrated on write) — plus optional `--vulns <file>`, `--design-doc <file>`, `--context <paths>`, `--seed <model-file>`, `--base <ref>`, `--fresh`. Build modes write `<target-dir>/<repo>-threat-model.md` per the skill's schema.md and are complete only when python3 -m traust.cli reporting lint reports ALL PASSED; finish by printing the path, the linter result, the top 5 threats by likelihood × impact, and the open questions.
