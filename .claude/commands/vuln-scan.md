---
description: "Scan source code for additional vulnerability candidates and deduplicate them against an existing audit."
---

Run a static source-code vulnerability scan of $ARGUMENTS using the vuln-scan skill. Load the skill at .claude/skills/vuln-scan/SKILL.md and follow its full procedure — derive the target's repo name/REPO_SLUG/SHORTSHA, scope from its threat model (`<repo>-threat-model.md`, or legacy THREAT_MODEL.md) or a quick recon, locate the `<repo>-security-audit.json` baseline (`--baseline`, beside the target, or in the findings tree), fan out one review subagent per focus area (read-only: no building, running, or network), dedupe candidates against the baseline into `known_findings`, assign campaign finding IDs (`{REPO_SLUG}-{SHORTSHA}-{NNN}`) with the shared five-level severity enum, run the per-finding confidence pass (unless `--no-score`), and write `<target-dir>/<repo>-vuln-findings.{json,md}` with `metadata.harness_version` stamped. `$ARGUMENTS` is `<target-dir>` plus optional `--baseline <audit.json>`, `--focus <area>` (repeatable), `--single`, `--extra <file>`, `--no-score`. Positioning: /secure-code-audit is the preferred baseline and /verify-remediation the way to update it after fixes; this scan supplements the baseline with new candidates. Findings are unverified — finish by pointing the user at `/triage <target-dir>/<repo>-vuln-findings.json --repo <target-dir>` and the follow-up-finding flow for folding verified results back into the baseline audit.
